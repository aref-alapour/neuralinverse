## ۲) رجیستر نقاط ضعف

شدت: 🔴 بحرانی (درست‌بودنِ ادعاهای ما را زیر سؤال می‌برد) / 🟠 مهم / 🟡 متوسط.

### الف) ساختاری

**S1 🔴 — هیچ بیلد کاملی از سورس وجود ندارد؛ تنها مسیر رسیدن کد به کاربر، جراحی
روی باندل مینیفای است.**
شاهد: `ls out` → وجود ندارد؛ `npm run compile` هرگز در این درخت اجرا نشده؛ همه‌ی
تست‌های زنده از ۹۷ پچِ `tools/live-patch.py` روی
`C:\Program Files\NeuralInverse\...\workbench.desktop.main.js` می‌گذرد.
پیامد: هر تغییر **دو بار** نوشته می‌شود (سورس + پچ مینیفای)، هم‌ارزی این دو هرگز
مکانیزه اثبات نشده، و اولین آپدیت رسمی برنامه هر ۹۷ پچ را MISSING می‌کند.
**ریشه‌ی بیشتر ضعف‌های پایین همین است.**

**S2 🔴 — سه stack ایجنت موازی (Q3، وضعیت 🔴).**
`void/` (ابزار native + MCP)، `neuralInverse/` (پروتکل JSON-block)، `powerMode/`
(پورت opencode) — سه پروتکل ابزار، سه مدل مجوز. هر قابلیت جدید باید سه‌جا پیاده
شود. سند خودمان اسمش را گذاشته «مسئله‌ی معماری اصلی پروژه»؛ هنوز حتی فاز ۰ (سند
معماری) شروع نشده.

**S3 🔴 — بزرگ‌ترین feature پروژه هرگز زنده اجرا نشده.**
Context Ledger (۱۱ کامیت، ۲۸ فایل type-check شده، ۶ فایل تست) روی نسخه‌ی نصبی
پورت نشده و مالک هیچ‌وقت آن را در استفاده‌ی واقعی ندیده. پیش‌فرضش هم `true` است
(`voidSettingsService.ts:341`) — یعنی در اولین بیلد از سورس، مسیر پیش‌فرضِ چت عوض
می‌شود بدون آنکه یک بار در دست کاربر تست شده باشد.

**S4 🟠 — PR #139 هیچ‌وقت توسط CI کامپایل یا تست نشده.**
شاهد: `gh pr checks 139` فقط دو چک برمی‌گرداند — `label` (fail) و `size` (fail).
هیچ‌کدام از ورک‌فلوهای واقعی (`ci`, `pr-win32-test`, `pr-linux-test`) اجرا نشده‌اند.

### ب) راستی‌آزمایی و پوشش

**V1 🔴 — از ۸۷ فایل تستِ موجود در سورس، گیت ما فقط ۶ تا را اجرا می‌کند.**
شاهد: `find src -name "*.test.ts" | wc -l` → ۸۷؛ کلید `tests` در
`tools/typecheck-slice.json` → ۶ فایل (همه ledger/stream/oss). آن «۹۶ تست سبز» که
گزارش می‌کنیم از همین ۶ فایل است. ۸۱ فایل تست دیگر فقط با `npm run test-node`
بعد از بیلد کامل اجرا می‌شوند — که طبق S1 هرگز اجرا نشده.

**V2 🟠 — type-check فقط روی ۲۸ فایل، و react src صفر پوشش دارد.**
`typecheck-slice.json` → `files` = ۲۸. تنها فایل feature بیرون‌مانده
`sendLLMMessage.impl.ts` است (`@ts-nocheck`). ضمناً `react/src/*.tsx` در هیچ slice ای
نیست و tsup/esbuild فقط transpile می‌کند — یعنی تغییرات UI (ازجمله فوتر دیروز)
هیچ‌وقت type-check نشده‌اند (W9).

**V3 🟠 — هیچ CI مخصوص خودمان وجود ندارد.**
`verify.mjs` فقط دستی اجرا می‌شود؛ هیچ hook یا workflow ای جلوی کامیتِ سبزنشده را
نمی‌گیرد. (`.github/workflows` در ریپو هست ولی sparse-checkout بیرونش گذاشته و آن
ورک‌فلوها هم مالِ upstream اند و روی PR ما اجرا نشدند — S4.)

**V4 🟠 — رِیس `_activeLoopStartMs` (W1).**
فیلد تک‌مقداری روی سرویس؛ دو حلقه‌ی همزمان مقدار هم را خراب می‌کنند → duration غلط
یا صفر. پچ باندل این باگ را **ندارد** (متغیر لوکال) — یعنی سورس و نسخه‌ی نصبی دو
رفتار متفاوت دارند، که دقیقاً خطرِ S1 است.
