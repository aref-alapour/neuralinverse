# Q9 — `NODE_TLS_REJECT_UNAUTHORIZED=0` روی کل حساب کاربر

- **اولویت:** **P0 (امنیتی)** | **برآورد:** S (تشخیص) + S (رفع) | **وضعیت:** 🔴
- **وابستگی:** ندارد — مستقل از کمپین بیلد ([Q7](07-source-build-campaign.md)) اجرا شود
- **کشف:** ۲۰۲۶-۰۹-۰۶، حین کمپین بیلد (هشدار node در خروجی هر دانلود npm/node-gyp)

## مسئله

`NODE_TLS_REJECT_UNAUTHORIZED=0` در سطح **User** ویندوز ست شده — نه فقط در process
این سشن. یعنی **هر پروسه‌ی node این کاربر** اعتبارسنجی گواهی TLS را خاموش دارد.

دامنه‌ی واقعی‌اش از «نصب npm امروز» خیلی بزرگ‌تر است:

- **خودِ NeuralInverse** (ادیتور نصب‌شده) که با کلیدهای واقعی به API های LLM وصل
  می‌شود — هر درخواستش قابل MITM است.
- همه‌ی سرورهای MCP که به‌صورت `npx` بالا می‌آیند (در همین ماشین ده‌ها پروسه‌ی
  فعال دیده شد).
- کل زنجیره‌ی نصب و دانلود هدرهای این کمپین.

نکته‌ی بدتر: چون در سطح User ست است، **ماه‌هاست فعال بوده** — نه از امروز.

## چرا «حذف env» راه‌حل کامل نیست

اگر علتِ اصلی یک پروکسی یا آنتی‌ویروس با SSL-scanning باشد، حذف متغیر باعث می‌شود
هر ابزار node ای با خطای گواهی بشکند و فشار برای برگرداندنِ متغیر ایجاد شود. رفع
درست دو قدمی است:

1. **root CA همان پروکسی/آنتی‌ویروس را وارد Windows trust store کن** (و در صورت
   نیاز `NODE_EXTRA_CA_CERTS` را به فایل PEM آن اشاره بده).
2. **سپس** متغیر User را حذف کن و بررسی کن npm/node/ادیتور همچنان کار می‌کنند.

## طرح

1. **تشخیص علت (S):** ببین کدام ابزار گواهی را جایگزین می‌کند — گواهی زنجیره‌ی
   `registry.npmjs.org` را بررسی کن؛ اگر issuer یک CA محلی است، همان مقصر است.
2. **ثبت مسیر CA (S):** فایل PEM را در مسیری پایدار بگذار و
   `NODE_EXTRA_CA_CERTS` را در سطح User ست کن.
3. **حذف متغیر ناامن (S):** `NODE_TLS_REJECT_UNAUTHORIZED` را از متغیرهای User
   حذف کن.
4. **راستی‌آزمایی (S):** `npm ping`، یک درخواست HTTPS از node، و یک چت واقعی در
   ادیتور — هیچ‌کدام نباید خطای گواهی بدهند و هیچ‌کدام نباید هشدار
   `NODE_TLS_REJECT_UNAUTHORIZED` چاپ کنند.
5. **چرخش کلیدها (تصمیم مالک):** اگر مسیر شبکه‌ی این ماشین قابل اعتماد نبوده،
   کلیدهای API که در این مدت استفاده شده‌اند باید rotate شوند. این تصمیم مالک است،
   نه پیش‌فرض این تسک.

## معیارهای پذیرش

- [ ] `NODE_TLS_REJECT_UNAUTHORIZED` نه در محیط User است و نه در محیط Machine
- [ ] `npm ping` و یک `https.get` ساده از node بدون خطا و بدون هشدار کار می‌کنند
- [ ] ادیتور نصب‌شده یک چت واقعی را بدون خطای گواهی کامل می‌کند
- [ ] تصمیم مالک درباره‌ی rotate کردن کلیدها ثبت شده (انجام شد / آگاهانه رد شد)
