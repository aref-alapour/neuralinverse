# سه تست owner برای بستن گیت G4 دسته‌ی حافظه

- **هدف:** M5، M2 و M1 هر سه 🟡 اند فقط به‌خاطر «تست owner» — کدشان کامیت و
  سبز است. این سه تست همان گیت را می‌بندند.
- **پیش‌نیاز:** نصب بسته‌ی تازه (زیر). تا قبل از آن نسخه‌ی نصبی ۲۶ کامیت عقب بود
  و این تست‌ها **بی‌معنی** بودند.
- **معیار:** هر تست شرط چهارم «انجام شده» را می‌سنجد — **سناریوی قابل‌مشاهده**.
  شاهد هر کدام یا روی دیسک است یا در خود UI؛ هیچ‌کدام «به‌نظر درست می‌آید» نیست.

## تست ۱ — M5: Ledger واقعاً می‌نویسد

> اول این، چون M1 و M2 هر دو رویش سوارند.

**اجرا:**
1. یک پوشه‌ی پروژه‌ی واقعی باز کنید (نه پوشه‌ی خالی).
2. در چت **۴ تا ۵ پیام** رد و بدل کنید — حداقل یکی‌شان کاری باشد که ابزار صدا
   بزند (مثلاً «فایل package.json را بخوان و بگو چند تا script دارد»).
3. در ترمینال، داخل همان پوشه‌ی پروژه:

```bash
ls .inverse/ledger/
cat .inverse/ledger/*/meta.json
wc -l .inverse/ledger/*/journal*.ndjson
```

**شرط عبور — هر سه با هم:**
- پوشه‌ای با شناسه‌ی thread ساخته شده
- `meta.json` فیلد `lastSeq` دارد
- **تعداد خطوط journal دقیقاً برابر `lastSeq`** ← این مهم‌ترین است: یعنی
  شماره‌گذاری بدون شکاف کار می‌کند (گاردِ CAS در M6)

**اگر نشد:** `contextLedgerEnabled` را در تنظیمات چک کنید. اگر خاموش بود این
تست شکست نیست — مهاجرت فلگ کار نکرده، که خودش یافته است.

## تست ۲ — M2: حافظه با واژگان متفاوت پیدا می‌شود

> این چیزی است که «حس Cursor» را می‌سازد. بدون آن، حافظه فقط واژگانی است.

**پیش‌نیاز مهم:** یک provider برداری واقعی تنظیم شود، وگرنه سیستم به fallback
واژگانی می‌افتد و تست معنای دیگری می‌دهد. ساده‌ترین گزینه‌ی محلی:

```bash
ollama pull nomic-embed-text
```

(یا در تنظیمات، کلید OpenAI/Mistral/OpenRouter — فهرست معتبر در فایل تسک M2.)

**اجرا:**
1. در چت بگویید: **«این را به یاد داشته باش: همیشه از pnpm استفاده کن، نه npm.»**
2. چت را ببندید و یک چت **جدید** باز کنید.
3. بپرسید: **«پکیج منیجر این پروژه رو عوض نکن.»** — توجه کنید هیچ کلمه‌ی
   مشترکی با جمله‌ی اول ندارد (نه «pnpm»، نه «npm»، نه «یاد»).
4. بعد بپرسید: **«بخش Agent Memory در system prompt ات را عیناً نشان بده.»**

**شرط عبور:**
- بلوکی به شکل `Agent Memory (N entries):` می‌آید
- خط مربوط به pnpm در آن هست
- و پسوندش **`(matched: vector:0.xx, …)`** است

**تفکیک مهم:**
| چیزی که می‌بینید | معنی |
|---|---|
| `matched: vector:0.xx` | ✅ بازیابی معنایی کار می‌کند — M2 کامل |
| `matched: term:…` فقط | 🟡 fallback واژگانی؛ provider برداری فعال نیست |
| اصلاً بلوکی نیامد | ❌ recall به مسیر تزریق نرسیده — گزارش کنید |

**تست دوم (backfill):** حافظه‌های قبل از فعال‌شدن provider باید بعد از ~۵ ثانیه
idle خودشان برداری شوند. یک حافظه‌ی قدیمی را با واژگان متفاوت بپرسید و ببینید
`vector:` می‌گیرد یا نه.

## تست ۳ — M1: گفتگو بعد از restart ادامه پیدا می‌کند

**اجرا:**
1. یک گفتگو با **حداقل ۳ نوبت** بسازید که context دارد — مثلاً یک فایل را
   بخوانید و درباره‌اش سؤال کنید.
2. یک نکته‌ی یکتا در آن بگویید (مثلاً «اسم رمز این کار Kestrel است»).
3. **ادیتور را کامل ببندید و دوباره باز کنید.**
4. همان گفتگو را باز کنید و بپرسید: **«اسم رمز چی بود؟»**

**شرط عبور:** «Kestrel» را بگوید بدون اینکه دوباره به او گفته باشید.

**تست دوم (بازیابی از بایگانی):** در همان گفتگو یا گفتگوی دیگر بگویید:
**«با recall_history بگرد ببین قبلاً درباره‌ی Kestrel چه گفتیم.»**
باید نتیجه‌ی واقعی از journal برگرداند، نه «چیزی پیدا نشد».

**آنچه انتظار **نداریم** کار کند (و شکست حساب نمی‌شود):** گفتگوهای
**workflow agent** بعد از restart شناسه‌ی تازه می‌گیرند —
`_conversationByAgent` هنوز `Map` در RAM است (`workflowAgentService.ts:143`).
این بخشِ باقی‌مانده‌ی M1 است، نه رگرسیون.
