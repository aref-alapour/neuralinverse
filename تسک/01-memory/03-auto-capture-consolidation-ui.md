# M3 — ثبت خودکار، تلفیق و مدیریت حافظه (Cursor-style Memories)

- **اولویت:** P1 | **برآورد:** M/L | **وضعیت:** 🔴 | **وابستگی:** M2 (بازیابی برداری)
- **هم‌ارز در Cursor:** Memories خودکار + صفحه‌ی مدیریت Memories + «این را به یاد داشته»

## هدف
سه چیز که Cursor در حافظه جلوتر است: (۱) ثبت **خودکار** ترجیحات/قواعد از دل گفتگو،
(۲) تلفیق و پاکسازی خودکار (dedupe/decay)، (۳) UI مدیریت حافظه (دیدن/ویرایش/سنجاق).

## وضعیت فعلی در کد
- ثبت حافظه فقط در پایان task با `_persistTaskMemory` در `neuralInverseAgentService.ts`
  (انواع موجود: pattern / preference / project-fact / error-fix / tool-usage / file-context)
- هیچ مکانیزم dedupe / decay / merge وجود ندارد (فقط eviction بر اساس relevance)
- هیچ UI برای دیدن محتوای حافظه وجود ندارد
- فلسفه‌ی پروژه (کامیت `9bc1183`): کارهای محلی بدون LLM — از همین الگو استفاده می‌کنیم

## طرح پیاده‌سازی

### الف) ثبت خودکار (Auto-capture)
1. **صریح:** تشخیص محلی (regex، بدون LLM) جملات دستوری کاربر در chat:
   «از این به بعد…»، «همیشه/هرگز…»، «remember…»، «prefer…» → toast
   «ذخیره در حافظه؟ [نوع: preference]» با پیش‌نمایش متن قبل از ذخیره
2. **غیرفعال:** گسترش `_persistTaskMemory` برای استخراج correction ها
   (کاربر agent را اصلاح کرده → نوع `pattern` یا `error-fix`)
3. **اصلاح تکراری:** اگر کاربر یک نوع اصلاح را ≥۲ بار تکرار کرد → پیشنهاد حافظه
   (همان toast) — شمارش با کلید نرمال‌شده‌ی پیام اصلاح
4. هر ثبت خودکار `source: auto` می‌گیرد تا در UI از حافظه‌های دستی قابل تمیز باشد

### ب) تلفیق (Consolidation)
5. job زمان‌بندی‌شده (بسته شدن IDE + تایمر روزانه؛ زیرساخت trigger موجود در
   `workflowTriggerManager` قابل استفاده است):
   - merge: اگر cosine دو ورودی > 0.92 → ادغام با به‌روزترین متن و جمع بسامد
   - decay: بدون دسترسی در ۳۰ روز → importance × 0.5 (حذف فقط زیر آستانه)
   - pin: ورودی‌های سنجاق‌شده هرگز decay نمی‌شوند

### ج) UI مدیریت حافظه
6. تب جدید «Memory» در `agentManagerPart.ts`:
   - لیست با فیلتر نوع / scope (workspace یا global) / منبع (auto یا manual)
   - ویرایش inline، حذف، سنجاق (pin)، افزودن دستی
   - نمایش «آخرین بار استفاده» و «چرا تزریق شد» برای شفافیت
7. scope دو سطحی: workspace-scoped (پیش‌فرض) و global (per-user در IStorageService سراسری)
