# ممیزی تسک‌های Context — هم‌ترازی مارکرها با کد (۲۰۲۶-۰۹-۰۸)

> هر ادعا با شاهد کد و دستور بازتولید. مارکر هر هفت فایل C1–C7 بازبینی شد.

## ۱) نتیجه‌ی هم‌ترازی

| تسک | مارکر قبلی | مارکر جدید | چرا عوض شد |
|---|---|---|---|
| C1 اتصال Context Engine | 🔴 | **🟡** | شش ابزار `context_*` ساخته و در همه‌ی حالت‌های چت (جز power/checks) در دسترس‌اند |
| C2 Context Gauge | 🔴 | **🟡** | `IContextUsageReport` + تولیدش در assembler + `getLedgerUsageReport()` وجود دارد؛ فقط UI نیست |
| C3 At-Mentions | 🔴 | **🟡** | `@file`/`@folder` کامل کار می‌کند (ارثی از Void) و به staging وصل است |
| C4 Pinned Context | 🔴 | **🟡** | `pinnedBlocks` در assembler پیاده و تست شده؛ مصرف‌کننده ندارد |
| C5 Repo Map | 🔴 | 🔴 | تأیید شد: هیچ امتیازدهی‌ای نیست |
| C6 Smart Auto-Context | 🔴 | 🔴 | تأیید شد: مسیر خودکار نیست (ولی معادل دستی هست — بخش ۳) |
| C7 Compaction UX | 🟡 | 🟡 | تأیید شد؛ «UX ندارد» تحت‌اللفظی درست است |

**عدد کل پروژه:** از `۴ ✅ / ۹ 🟡 / ۳۷ 🔴` به **`۵ ✅ / ۱۲ 🟡 / ۳۳ 🔴`**
(چهار تای آن از این ممیزی، یکی Q7 که با `00674fe` بسته شده بود و در سند نیامده بود).

```bash
for f in $(find "تسک" -name "*.md" -not -name "README.md" -not -name "00-*"); do \
  grep -m1 -o "وضعیت:\*\* *[^ |]*" "$f"; done | sort | uniq -c
```

**نکته‌ی روشی:** هیچ‌کدام از این چهار مورد «کار انجام‌نشده‌ای که یواشکی انجام شده»
نیست. سه‌تایشان محصول جانبی کار M5/Ledger بودند و یکی (C3) اصلاً ارثی از Void است.
یعنی مشکل، **دریفت وضعیت** بود نه ادعای دروغ — همان R1 در رجیستر Q8.

## ۲) بازبینی گزارش zCode

گزارش zCode در مجموع **درست و صادقانه** است، ولی دو نوع خطا دارد:

### آنچه درست بود (و من اول اشتباه کردم)
- **ledger زنده و S3 بسته است.** من اول `.inverse/ledger` را در همین ریپو گشتم و
  چیزی نیافتم و گفتم باز است. zCode درست می‌گفت — ledger در ورک‌اسپیس **دیگری**
  است: `escapezoom_dev/.inverse/ledger`. تأیید مستقل:

  | thread | `meta.lastSeq` | خطوط journal | بیشینه‌ی seq | gapless |
  |---|---|---|---|---|
  | `064b24a1` | ۲ | ۲ | ۲ | ✅ |
  | `0b9bc4b4` | ۴ | ۴ | ۴ | ✅ |
  | `ac7d2eef` | ۲ | ۲ | ۲ | ✅ |
  | `b65376c7` | ۲۹ | ۲۹ | ۲۹ | ✅ |

  zCode برای thread چهارم عدد ۷ داده بود؛ الان ۲۹ است — یعنی آن thread بین دو
  بررسی فعال بوده. **این خودش شاهد بهتری است**: ledger زیر بار واقعی هم gapless
  مانده. سند وضعیت اصلاح شد.
- `.claude/` واقعاً untracked و ایگنور‌نشده است (شامل `CLAUDE.md` و `skills/`).
- کامپایل سبز است. مستقل تأیید شد (بخش ۴).

### آنچه نادرست بود
- **C1 «هیچ wiring ای ندارد» غلط است.** zCode در `chatThreadService` گشته، ولی
  ابزارها آنجا وصل نمی‌شوند — مسیرشان `prompts.ts` (ثبت در `builtinTools`) و
  `toolsService.ts` (پیاده‌سازی) است. تله‌ی احتمالی: نام‌ها snake_case اند، پس
  `grep searchSymbols` هیچ‌چیز پیدا نمی‌کند ولی `context_search_symbols` می‌کند.
- **برای C2/C3/C4 شاهد «—» گذاشته شده** یعنی جست‌وجو نتیجه نداده، ولی از آن
  «انجام نشده» نتیجه گرفته شده. هر سه بک‌اند یا بخش کارکردی دارند.

**درس قابل ثبت:** «grep چیزی پیدا نکرد» شاهدِ نبودن نیست. برای این کدبیس دو تله
تکرار شد: نام‌های snake_case، و اینکه قابلیت‌ها در لایه‌ای غیر از جایی که انتظار
می‌رود وصل می‌شوند.

## ۳) آیا هنوز به این تسک‌ها نیاز داریم؟

| تسک | هنوز لازم؟ | تغییر نسبت به طرح اصلی |
|---|---|---|
| **C2** gauge | **بله — و حالا ارزانتر** | بک‌اند هست؛ فقط UI. **پیشنهاد: اولین کار context.** |
| **C7** compaction UX | **بله** | ولی حالا باید **دو** مسیر را پوشش دهد (ledger + legacy)، که در طرح نبود |
| **C4** pinned | **بله، ولی کوچک‌تر** | کار assembler حذف شد؛ فقط storage + UI + وصل کردن |
| **C3** منشن‌ها | **جزئاً** | `@file`/`@folder` تمام است. فقط `@symbol`/`@agent`/`@web` مانده |
| **C1** بقیه | **بله** | ابزارها تمام؛ `contextBudgets` و Ctrl+K و ماتریس مانده |
| **C5** repo map | **بازبینی اولویت** | با وجود ابزارهای `context_*`، مدل می‌تواند خودش پیدا کند — ارزشش کم‌تر از قبل است |
| **C6** auto-context | **بازبینی اولویت** | `context_semantic_search` معادل دستی‌اش را می‌دهد (بخش زیر) |

### درباره‌ی C6 — چیزی که طرح ندیده بود
ابزار `context_semantic_search` روی `hybridSearchService` سوار است و مدل می‌تواند
صدایش بزند. تفاوت باقی‌مانده با C6 کامل:

| طرح C6 | چیزی که الان هست |
|---|---|
| خودکار، قبل از ساخت پیام | فقط اگر مدل تصمیم بگیرد |
| گسترش ۱-هاپی با import graph + rerank | جست‌وجوی تخت |
| attribution («چرا این فایل آمد») | ندارد |

**توصیه:** C6 و C5 را تا بعد از C2 معلق نگه دارید. تا وقتی gauge نداریم،
نمی‌دانیم مدل چقدر از ابزار semantic استفاده می‌کند — یعنی تصمیم بی‌داده است.

## ۴) دو یافته‌ی بیرون از تسک‌ها

**الف) گیت تایپ‌چک با تنظیمات پیش‌فرض کار نمی‌کند.** دستوری که `CLAUDE.md`
اجباری کرده (`npm run typecheck-client`) در این فورک وجود ندارد، و اجرای مستقیم
`tsc` با هیپ پیش‌فرض ۴GB به OOM می‌خورد (`FATAL ERROR: … heap out of memory`،
خروج ۱۳۴). با ۸GB — همان عددی که خودِ اسکریپت `compile` دارد — **سبز است:**

```bash
NODE_OPTIONS="--max-old-space-size=8192" npx tsc -p src/tsconfig.json --noEmit
# → ۰ خطا (شامل گارد کامیت‌نشده‌ی voidAutoUpdaterService)
```

این باید یا در `CLAUDE.md` اصلاح شود یا به‌صورت یک اسکریپت npm ثبت شود، وگرنه هر
بازبین بعدی همین ۱۹۰ ثانیه را هدر می‌دهد و نتیجه‌ی گمراه‌کننده می‌گیرد.

**ب) `matrix.md` (تحویل‌دادنی C1) هنوز ساخته نشده** — این ممیزی جایش را نمی‌گیرد،
چون ماتریس باید «نقطه‌ی ورودی × منبع context» را پوشش دهد و اینجا فقط وضعیت
تسک‌ها بررسی شد.
