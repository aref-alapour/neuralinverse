## بخش ب — قرارداد اجرای هر گام (برای همه‌ی گام‌ها یکسان)

```text
برای هر گام دقیقاً این چرخه را اجرا کن و بین مرحله‌ها گزارش بده:

1. بررسی: فایل تسک مربوطه را بخوان + کد فعلی نقاط تماس را بخوان.
   قبل از نوشتن کد، در ≤۱۰ خط بگو: چه فایل‌هایی می‌سازی، چه فایل‌هایی را دست
   می‌زنی، و چه چیزی را نمی‌شکنی. اگر چیزی در تسک با کد فعلی نمی‌خواند، همان‌جا
   بگو — حدس نزن.
2. پیاده‌سازی روی سورس (نه فقط live-patch). استایل TypeScript همان فایل‌های
   اطراف؛ بدون dependency جدید؛ بدون کپی از منابع بیرونی.
3. تست‌های واحد همان گام را بنویس و اجرا کن. سبز نشد، گام تمام نشده.
4. کامیت محلی با پیام انگلیسی روشن (Problem → Fix).
5. پورت به `tools/live-patch.py` + اجرای elevated + `--verify` سبز.
6. به من بگو restart کنم و سناریوی تست را دقیق بنویس (چه کاری بکنم، چه چیزی
   باید ببینم، کجا باید فایل/لاگ را چک کنم).
7. بعد از تأیید من: چک‌باکس‌های معیار پذیرش آن گام را در فایل تسک تیک بزن و
   جدول وضعیت `تسک/README.md` را به‌روز کن.
8. فقط اگر صراحتاً گفتم «بفرست»: شاخه‌ی تمیز فقط با تغییرات سورس (بدون
   `تسک/`، `tools/`، `AGENTS.local.md`) + issue/PR حرفه‌ای انگلیسی.

قواعد ثابت در کل این مسیر:
- هیچ مسیری اجازه ندارد پیام را واقعاً حذف کند. هر جا `splice`/`shift`/
  `length = 0` روی تاریخچه دیدی، یا حذفش کن یا برایم توضیح بده چرا لازم است.
- هر قابلیت جدید پشت flag با پیش‌فرض امن؛ خاموش کردن flag باید رفتار قبلی را
  بی‌کم‌وکاست برگرداند.
- degrade تدریجی: نبود LLM / نبود embedding / نبود دسترسی دیسک باید مسیر را
  کند کند، نه بشکند. هیچ خطای قرمزی در کنسول نباید بماند.
- بعد از هر گام یک خط بگو چقدر توکن/هزینه/زمان صرفه‌جویی شد یا اضافه شد.
```

## بخش ت — دروازه‌های توقف (اگر اینها رخ داد، ادامه نده و بپرس)

1. اگر برای انجام گامی لازم شد از یک پروژه‌ی بیرونی کد برداری → **توقف**، بپرس.
2. اگر گامی مجبورت کرد داده‌ای را واقعاً حذف کنی → **توقف**، بپرس.
3. اگر پورت live-patch برای تغییری ممکن نبود → **توقف**؛ کامیت بدون پورت
   یعنی گام تمام‌نشده.
4. اگر تست مقیاس نشان داد payload با طول thread رشد می‌کند → **توقف**؛ یعنی
   قانون D1 یا D5 جایی نقض شده.
5. اگر خواستی به upstream چیزی بفرستی → فقط با «بفرست» صریح من.
6. اگر `python tools/live-patch.py --verify` سبز نیست → **هیچ تست زنده‌ای را معتبر
   اعلام نکن**، حتی اگر apply بدون خطا تمام شده باشد. (درس ممیزی ۲۰۲۶-۰۹-۰۵)
7. اگر `node tools/verify.mjs` درصد پوشش را گزارش نمی‌کند یا فهرست فایل‌های
   چک‌نشده را پنهان می‌کند → **توقف**؛ یک سبزِ گمراه‌کننده از هیچ بدتر است.
